- Lead reservation/contract state changes ("Assinou", "Desistiu", fee waiver) go through SECURITY DEFINER RPCs (sign_lead_contract, give_up_lead, reserve_room_without_fee) so room blocking and lead updates are atomic.
- Pending-agreement and contract personal-data rules live in src/lib/leadContractRules.ts (pure, unit-tested) and are reused by all lead dialogs.
- Nationality and phone inputs for people (leads, residents, candidate form) use the shared country list in src/lib/countries.ts (NationalitySelect/PhoneInput in src/components/CountryFields.tsx); nationality is stored in its Portuguese form and phones as "+<dial> <number>", so contracts and lusophone detection keep working from one source.
- Payments are never deleted to correct mistakes: they are voided via void_payment (status/void_reason/voided_by), every sum (rent_charge_balance, evaluate_lead_won, fee totals, checklists) filters status = active, and contract deposit totals are always recomputed from active payments by trigger/register_deposit_payment so they cannot drift. Moloni-imported payments (source = moloni) are not voidable in the app.
- Candidate documents are typed (lead_documents.kind) and never deleted; replacement requests reuse the form token via pedir-documentos-candidatura and the public /candidatura/:token/documentos page, and the docs badge rule lives in src/lib/leadDocuments.ts (unit-tested), so staff always see the latest file per type without reopening the full form.
- The resident page Documents section merges candidate files (lead_documents via the resident’s contracts/stays leads) with staff uploads (resident_documents, bucket resident-documents under staff/<resident_id>/); files are linked, not copied, and never deleted, so there is one source per file.
