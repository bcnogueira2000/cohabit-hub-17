- Lead reservation/contract state changes ("Assinou", "Desistiu", fee waiver) go through SECURITY DEFINER RPCs (sign_lead_contract, give_up_lead, reserve_room_without_fee) so room blocking and lead updates are atomic.
- Pending-agreement and contract personal-data rules live in src/lib/leadContractRules.ts (pure, unit-tested) and are reused by all lead dialogs.
- Nationality and phone inputs for people (leads, residents, candidate form) use the shared country list in src/lib/countries.ts (NationalitySelect/PhoneInput in src/components/CountryFields.tsx); nationality is stored in its Portuguese form and phones as "+<dial> <number>", so contracts and lusophone detection keep working from one source.
- Payments are never deleted to correct mistakes: they are voided via void_payment (status/void_reason/voided_by), every sum (rent_charge_balance, evaluate_lead_won, fee totals, checklists) filters status = active, and contract deposit totals are always recomputed from active payments by trigger/register_deposit_payment so they cannot drift. Moloni-imported payments (source = moloni) are not voidable in the app.
- Candidate documents are typed (lead_documents.kind) and never deleted; replacement requests reuse the form token via pedir-documentos-candidatura and the public /candidatura/:token/documentos page, and the docs badge rule lives in src/lib/leadDocuments.ts (unit-tested), so staff always see the latest file per type without reopening the full form.
- The resident page Documents section merges candidate files (lead_documents via the resident’s contracts/stays leads) with staff uploads (resident_documents, bucket resident-documents under staff/<resident_id>/); files are linked, not copied, and never deleted, so there is one source per file.
- Resident document ZIP exports use the browser-only residentDocumentZip helper and signed URLs for each original bucket; this preserves private access and tests duplicate filenames without modifying stored documents.
- Resident profile edit values use residentProfileValue to recognize candidate codes and legacy contract labels while preserving custom profiles; this prevents empty selects for stored data.
- Extra services ("Outras receitas") are extra_charges debits from service_catalog (or custom name), created/voided only via create_extra_charge/void_extra_charge RPCs and paid via payments.extra_charge_id, so they flow into contract_ledger and the balance like rents; staff-only, no resident access yet.
- Anonymous visitors have no table grants in public except INSERT on requests/stays (public forms); public flows use SECURITY DEFINER RPCs, and roles are assigned only via set-user-role, handle_new_user or approve_profile, so no client can escalate privileges.
- Staff-only resident notes live in resident_internal_notes (residents.internal_notes is deprecated and kept empty) and a trigger blocks non-staff from changing account_status/resident_id/email/user_id on profiles, because residents can read their own residents/profiles rows.
- Financial guardrails live in DB triggers (no delete of payments/extra_charges, immutable payment amounts/links, no overpayment, contracts deletable only without payments/extras, no overlapping reserved/active contracts per resident, audit_log on financial tables), so every client and RPC is bound by the same rules.

## Política de notificações
- Só se notifica o que exige uma ação humana e não é visível noutra página da app.
- Tipos em uso: form_submitted, docs_received, request_new, request_comment, request_status, contract_ending, deposit_pending (os dois últimos uma única vez por utilizador e contrato).
- Estados financeiros como rendas em atraso vêem-se no portal de pagamentos e não geram notificações.
- Supplier costs (/finance/costs) read cost_invoices + cost_invoice_lines with DB triggers enforcing classification/payment rules; dashboard maths lives in src/lib/costInsights.ts (unit-tested) and invoice reading goes through the staff-only extract-cost-invoice function, so the client never trusts its own totals.

- Leitura de faturas de custo: o QR fiscal é extraído no browser (src/lib/invoiceQr.ts, pdfjs-dist + jsQR, com polyfill de Map.getOrInsertComputed exigido pelo pdf.js v6) e enviado como qr_text à função extract-cost-invoice, que faz merge QR+IA em _shared/ptQr.ts; a pré-visualização de PDF na gaveta usa renderização pdf.js (CostFilePreview), nunca iframe, para funcionar no telemóvel.
- Supplier invoices go to Moloni only via the manager-only moloni-supplier-invoice function, always as draft (status 0) in series FORN with your_reference "LCCOM-<last number block>" (_shared/moloniRef.ts, tested); it checks duplicates by supplier + reference, records the send with the user's session (cost triggers require staff), and a trigger locks moloni_* fields once sent so an invoice is never sent twice.
